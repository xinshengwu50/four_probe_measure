# PS/PL 接口契约审查

## 工作流程
1. 列出提供方、消费方和当前接口版本，从实际RTL读写译码核对PS常量，不依赖旧文档。
2. 契约包含地址/范围/访问副作用、位宽/符号、复位值、单位/缩放、超时、序号、错误及缺失数据语义。
3. 从原帧到物理量逐层推导；ADC零码与前端探针零码分别计算。窗口应从同一逆变换生成，并检查写后回读。
4. 新鲜度由原子序号+数据证明；相同码可以是新样本。READY/ACK说明序号绑定，防止旧ACK清掉新结果；多寄存器快照还需锁存或读序号前后校验，ACK_SEQ本身不保证快照原子性。
5. 试探选档与最终测量的数量/质量门限分开；零样本不得返回合格零值，缺失用null+quality_flags。
6. 优先写不一致和边界用例；有授权才修改两端并提升版本。生成地址表只保证机械部分，人工语义仍需审查。
7. 输出契约表、差异和兼容/部署要求。

## 何时用 / 何时不用

**用**：改了 RTL 寄存器但 PS 侧没跟着改；同一个物理量在 PL 和 Python 里单位/符号/缩放对不上；怀疑读到的是上一个窗口的旧数据；**准备删除"看起来没人用"的 RTL 模块前**。

**不用**：接口只有一个寄存器且已被端到端测试覆盖时，逐条走契约表是浪费。先看那一个寄存器的读写两端是否一致。

## 使用与输出

给本流程：RTL 读写译码原文、Python 侧常量定义、异常读数。输出使用 [报告模板](assets/report.md)。缺少用户独占事实时一次询问最阻塞的问题；不要把历史工程参数迁到新板。

一句话就能启动：

> 我打算删除 `all_final.v` 里的 `meas_chain` 模块，因为搜不到它的输出被谁用。请只读审查：`rho`/`Rs` 从 RTL 到 Python 的完整消费者链是什么，删掉之后哪些功能会静默失效。不要修改任何文件。

判"死代码"必须沿 AXI 外设边界追到消费方，搜信号名和数网表单元都会给假阴性——见 [实例复盘](../../evidence/worked-examples.md) 第一例。
