# 机电安全调用链与互锁审查

## 工作流程
1. 先获取实际机械方向、标定、硬限位、驱动保持、传感器、STOP能力和复位后位置可信度；不能从软件步数推断机构安全。
2. 从真实服务/Notebook入口追踪ARM、HOME、MOVE、采集、异常、finally；函数存在不代表被调用，旧状态机也必须覆盖。
3. 建立命令×危险状态矩阵：下压、横移、撤回、回零、停止分开。横移要求可信回零+足够间隙，不仅要求其他轴busy=0。
4. 撤回可在确定只远离样品时采用独立安全路径；不能笼统让所有HOME绕过保护。Z步数只是估计，不是编码器证明。
5. 心跳在首个硬件使能前覆盖；阻塞轮询检查取消。正常关断、外部复位、无法确认电流关闭分支分别审查。解除武装不要吞掉复位锁存，退出线程需要join。
6. 检查拒绝命令的状态/错误可观测性及命令接受握手；旧DONE不得当新动作成功。STOP失败保留原异常与停止错误，不自动重试运动。
7. 先离线状态矩阵和反证测试，再明确授权的无负载/低速上板；默认动作授权False，不假设X轴即时STOP。

## 何时用 / 何时不用

**用**：新加了运动或执行器入口；看门狗/互锁/急停的逻辑改过；发现"函数写了但没接进真实调用链"；准备上电做真实动作之前。

**不用**：只是调参数（速度、加速度）而不改调用链和安全逻辑时，先做离线预览即可——见 [pynq_motion_tuning](../../pynq_skills/pynq_motion_tuning/README.md)。

## 使用与输出

给本流程：真实入口文件、机械标定与限位、STOP 能力说明、授权范围。输出使用 [报告模板](assets/report.md)。缺少用户独占事实时一次询问最阻塞的问题；不要把历史工程参数迁到新板。

一句话就能启动：

> 我给运动加了新的"撤回"命令。请只读审查真实调用链：撤回是否可能被互锁挡住、是否只在确定远离样品时才走独立安全路径、STOP 失败时是否保留了原异常。不要上电，不要执行任何动作。
