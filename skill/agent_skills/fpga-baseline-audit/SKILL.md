# FPGA 构建与部署来源审计

## 工作流程
1. 先确认用户指定的权威工程、目标板卡和只读边界；目录名称或文件时间不能证明版本。
2. 读最新任务日志、工程README；记录代码、封装IP、实际综合源、生成副本与部署位置。通过 Tcl source清单/构建日志确认实际来源，不仅搜索同名文件。
3. 比较源哈希；说明有意的差异，不擅自覆盖封装源或生成文件。引用 PYNQ工具 source_identity.py 可做只读字节比较，但它不能发现Vivado实际选择了哪个文件。
4. 核对同次构建的bit/hwh、器件、地址、IP身份和协议VERSION；哈希相同仅证明文件相同，不证明板上加载。
5. 需要变更构建时先列范围和回退；实际重建走Tcl，不手改xpr。保留多串口、XDC和用户改动。
6. 部署前给出安全停机步骤；只有明确授权才下载。实际读取VERSION及IP映射后才标注BOARD验证。
7. 报告每层证据，不把综合通过当成硬件通过。

## 使用与输出
读 [案例及边界](references/case.md) 判断是否与当前场景相符。输出使用 [报告模板](assets/report.md)。缺少用户独占事实时一次询问最阻塞的问题；不要把历史工程参数迁到新板。

用户请求示例：请用此流程只读审查提供的工程，给出可复现证据、风险及下一项最有区分力的测试。
